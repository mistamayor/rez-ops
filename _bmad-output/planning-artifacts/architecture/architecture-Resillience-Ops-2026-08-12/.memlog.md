- (decision) AD-11 (new) Evidence boundary. Binds: shared schema module, ledger-core, Voice. Prevents: a reasoning-layer claim (e.g. 'this runbook looks stale') existing only as prose with no attributable source, undermining never-hide-uncertainty at the reasoning layer the same way an unattributed RawFact would at the data layer. Rule: a new shared schema type EvidenceBundle (claim, confidence: float 0-1, evidence: list of EvidenceRef, reasoning, generated_at) where each EvidenceRef points back to an already-ingested RawFact's source or a LedgerRecord field -- never inline-duplicates fact content, only cites it. EvidenceBundle.confidence is a claim-level plausibility score distinct from LedgerRecord.confidence's agent-verified/manual/unknown enum (AD-5) -- the two are never conflated or substituted for each other.
- (decision) AD-11 continued: EvidenceBundle authorship vs domain logic boundary [ASSUMPTION]. Voice assembles the claim/reasoning text (this is reasoning, not domain-logic computation -- AD-1's prohibition covers freshness/confidence/ownership computation, not structuring a citation over facts ledger-core already computed). But persistence goes through a new ledger-core write tool only (mirrors AD-6's drafts mechanism exactly: Voice calls it, ledger-core is the sole writer) -- Voice never writes ledger_data/ directly. Stored one-file-per-bundle at ledger_data/evidence/{evidence_id}.md, same human-readable/git-diffable convention as drafts.
- (decision) AD-12 (new) ActionProposal + Policy Engine. Binds: ledger-core, shared schema module, Voice. Prevents: (a) conflating drafted human-readable outbound content (AD-6's Draft, unchanged) with a structured, policy-evaluated system operation -- these need different schemas and different eventual consumers; (b) the LLM ever deciding for itself whether an action is permitted, which is the one property this whole layer exists to guarantee. Rule: ActionProposal (action, target: artifact_type/artifact_id, reason, evidence: list of EvidenceBundle refs, impact, policy_decision) is created by Voice calling a new ledger-core tool naming a fixed action-vocabulary identifier (never freeform) and citing at least one EvidenceBundle -- a proposal with zero evidence is invalid, rejected the same way empty Draft fields already are. Ledger-core -- never Voice -- computes policy_decision (automatic | requires_approval | denied) by resolving the named action's config-declared risk/impact against the target's criticality (from LedgerRecord/config) and the cited evidence's confidence, exactly extending AD-5's existing 'ledger-core exclusively computes derived values' principle rather than inventing a new exception to it.
- (decision) AD-12 continued: Never clause -- no executor exists in this phase. Rule: policy_decision is recorded, never acted on -- even an 'automatic' decision triggers no external write; nothing in this phase calls an external write/send API (extends AD-6's existing prohibition to the new object). Building an Executor that actually performs an approved action is an explicit, separate, later architectural decision requiring its own AD before any code writes externally -- out of scope here. Stored one-file-per-proposal at ledger_data/action_proposals/{proposal_id}.md, mirroring drafts'/evidence's convention.
