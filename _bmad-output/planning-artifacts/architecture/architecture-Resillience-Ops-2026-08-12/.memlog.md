- (decision) AD-1 Paradigm: three-layer Connector / Ledger-Core / Runtime split (Sensors-Ledger-Voice). Binds: all. Rule: connectors are dumb read-only fetch+normalize MCP servers; ledger-core is sole owner of the Freshness Ledger and all derived computation; the agent runtime (Claude Code or any MCP client) only orchestrates and presents, never holds domain logic
- (decision) AD-2 Server topology: one MCP server per data-domain connector (calendar, ticketing, git, CMDB) plus one separate ledger-core MCP server. Binds: all connector/core components. Prevents: a monolithic server accreting mixed responsibilities and bloating every session's tool/context budget (Claude Code docs explicitly warn connected-server tool lists load into every session context). Rule: new domains = new connector server, never extend an existing server's scope
- (decision) AD-3 State mutation: append-only event log with materialized projection. Binds: ledger-core. Prevents: silent unaudited edits to freshness/ownership state that destroy the history the trust-layer non-negotiable requires. Rule: all state changes are appended as immutable timestamped events to a git-committed per-artifact-type log; current state is always a pure recomputed projection over the log, never hand-edited in place
- (decision) AD-4 Shared ledger schema ownership. Binds: connectors + ledger-core. Prevents: each connector inventing its own record shape for last-verified/owner/tier/etc, producing data ledger-core cannot merge. Rule: one shared, versioned schema module defines every artifact-type record shape; every connector and ledger-core import it rather than declaring ad hoc fields
- (decision) AD-5 Confidence/coverage computation ownership. Binds: ledger-core only. Prevents: connectors independently guessing confidence scores with inconsistent methodology, undermining the never-hide-uncertainty non-negotiable. Rule: confidence/coverage values are computed exclusively by ledger-core from raw connector facts using one documented method; connectors report only raw timestamps/records, never a confidence score
- (decision) AD-6 Draft-not-send output boundary. Binds: ledger-core, any future write-capable connector. Prevents: an accidental or later-added write-back path bypassing the human-approval non-negotiable from the brief. Rule: any agent-authored outbound content is written only to a git-tracked drafts/ queue as a pending record; no component calls an external send/write API directly in v1
